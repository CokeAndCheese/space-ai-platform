# Space AI Platform — 单工作区研发与里程碑备份流程

> 生效日期：2026-08-21
> 模式：单工作区＋本地轻量 Git＋里程碑手动备份
> 流程所有者：`space AI platform产品经理-项目总控`

## 1. 唯一工作区

所有研发写入统一使用：

```text
/Users/mac/Documents/Codex/space AI platform
```

不再创建或使用额外 worktree，不以 PR 作为本地研发必经流程。Codex 可以在该目录管理本地 `codex/*` 任务分支；同一时刻只允许一个任务分支处于写入状态。已有旧 worktree 只在确认没有独有改动后退出使用；未经用户授权不做破坏性目录清理。

## 2. 角色派发与写入调度

### 2.1 派发顺序

- 产品经理先把已批准工作包按职责匹配到项目内现有 `职责-分工内容` 长期角色对话，再向该角色派发；主对话内部临时子 Agent 不得优先于合适的长期角色。
- 只有没有合适长期角色、需要一次性新鲜独立审查、对应角色不可用或受限，或上下文隔离具有明确价值时，才可使用临时子 Agent。启用时记录所映射的现有岗位职责、一次性范围、原因和同步对象。
- 临时子 Agent 完成后，产品经理把必要结论、证据、风险、依赖和阻塞同步给对应长期角色；若确无对应角色，由产品经理接收结论并判断是否提出正式人员调整。临时子 Agent 不获得长期岗位、持续所有权、独立汇报关系或默认后续任务；若反复出现无角色承接的职责缺口，按人员提议流程处理，不以临时子 Agent 静默填补。
- 产品经理始终保留工作拆解、调度、冲突裁决、写入队列控制、集成验收和用户汇报。

#### 派单前 fail-closed 记录门禁

- 每个实施或审查工作包派发前，产品经理必须在当次内部调度记录中写明已匹配的项目长期角色负责人。
- 改用主对话内部临时子 Agent 时，派发前还必须同时写明：长期角色不适用或不可用的原因、临时 Agent 映射的现有岗位、完成后回同步的长期角色对话。
- 任一必填项缺失时门禁关闭：不得派发临时子 Agent，应停止并先完成角色匹配与记录；不能以事后补记替代派单前证据。
- 该记录只用于内部调度和验收追踪，不要求向用户逐项汇报。用户仍只接收决策问题、重大风险、人事变动和里程碑结果；本门禁不增加人员，也不改变职责或汇报关系。

### 2.2 单一写入队列

- 产品经理维护单一任务分支、写入队列和文件所有权表。
- 长期角色对话的派发优先级不等于即时写入权；任一时刻只允许一个实现任务修改代码或文档。
- 技术负责人、QA 和其他人员可以并行只读审查，但不能在实现负责人写入时修改同一工作区。
- 负责人切换前必须报告变更文件、验证结果、未完成项和工作区状态；产品经理明确完成所有权交接后下一人才能写入。
- 紧急缺陷会暂停当前写入者，再安排新的明确负责人，不允许抢写。

## 3. 轻量 Git

Git 只承担四项职责：

1. 显示精确文件和代码差异。
2. 保存可恢复的本地检查点。
3. 在缺陷出现时定位和恢复单个文件或变更。
4. 保存已验收里程碑的本地历史。

日常不使用 worktree、并行分支、rebase、cherry-pick 或 PR。Codex 可为已批准工作包创建本地 `codex/*` 任务分支。允许的本地 commit 必须满足：

- 变更范围已经产品经理核对。
- 相关测试和审计已经通过，或失败/例外已明确记录。
- 使用精确文件路径暂存，不得使用 `git add .`。
- `src/model-manifest.json` 的现有用户修改不得被意外暂存。
- commit 信息说明交付内容或里程碑。

任务分支通过验证和产品验收后可以合入本地 `main`，再在确认安全后关闭本地任务分支。项目当前不连接 GitHub：禁止 fetch、pull、push、PR、远程分支检查/删除和远端历史合并；只有用户未来作出新决策后才重新评估。发布和部署也不属于轻量 Git 默认授权。

## 4. 普通检查点

普通检查点用于高风险或跨日工作，不代表里程碑完成：

```text
负责人完成一个可验证切片
→ 运行相关检查
→ 产品经理审查 diff 和范围
→ 精确暂存并创建本地 checkpoint commit
→ 继续下一切片
```

是否创建检查点由产品经理根据改动风险决定，不要求用户逐次操作。

## 5. 里程碑关闭流程

```text
所有工作包完成
→ 技术负责人完成架构/接口复核
→ QA 独立验收
→ 产品经理核对范围、证据和遗留风险
→ 用户完成里程碑决策/验收
→ 创建本地里程碑 commit
→ 用户执行外部手动备份
→ 用户确认备份完成
→ 更新 PRODUCT_CONTEXT / DECISION_LOG
→ 开启下一里程碑
```

用户未确认外部备份完成前，不开始下一个高风险里程碑。

## 6. 手动备份清单

### 普通项目备份应包含

- 源码、文档、脚本和 Git 仓库元数据。
- `public/models/` 等未由 Git 跟踪但产品运行需要的模型资产。
- 当前模型清单及 metadata 规范。
- 本里程碑验收报告、决策日志和组织架构。

### 可以排除

- `node_modules/`。
- `dist/` 或其他可重新生成的构建产物；若该里程碑需要保留可部署制品，则单独保留并记录哈希。
- 临时缓存、日志和测试残留。

### 敏感配置

- `.env.local` 等真实凭据不得混入普通项目压缩包。
- 如确需备份，应使用单独的加密存储，并记录凭据轮换和恢复责任。
- 不在聊天、文档、commit 或备份清单中记录凭据值。

### 建议命名

```text
space-ai-platform_M0_YYYY-MM-DD_HHMM
space-ai-platform_M1_YYYY-MM-DD_HHMM
```

备份完成后，用户只需向产品经理确认“里程碑 Mx 备份完成”。

## 7. 恢复原则

- 单文件或单次代码错误：优先用 Git diff/history 精确恢复。
- 整个工作目录损坏、磁盘故障或 Git 元数据损坏：使用最近一次里程碑手动备份。
- 模型资产损坏：从里程碑资产备份恢复并重新运行 metadata 校验。
- 敏感配置丢失：从加密凭据存储恢复；无法确认安全性时先轮换，不从普通项目备份复制。

## 8. 当前过渡事项

- 当前 `main` 相对已记录的 `origin/main` 为 ahead 6、behind 2；这只是历史远端状态，不影响本地研发。不得主动访问远端核对或同步。
- 当前主工作区有用户拥有的 `src/model-manifest.json` 修改，必须继续排除在非相关提交之外。
- 任何分支切换如果会要求移动、stash、提交或覆盖该用户修改，必须停止并请求对应授权。
- 现有人员任务正在从旧 Codex worktree 切换到保存的单一项目目录；切换完成前不得开始新的写入工作。

## 9. R1 本地非污染门禁

`npm run dev` 和 `npm run build` 不再通过 `predev` / `prebuild` 自动调用模型清单生成器。模型清单刷新保留为显式命令：

```text
npm run list-models
```

这是有意写回 `src/model-manifest.json` 的命令。只有在用户明确要求重建清单，且已经备份现有文件并确认预期差异后才能运行；常规开发、构建和 R1 验收不得把它作为隐式前置步骤。

R1 的统一本地入口是：

```text
npm run verify:r1
```

门禁使用固定的 Node 可执行文件和固定 argv，直接运行 topology 四组回归、三组边界审计、`vue-tsc --noEmit` 和 `vite build`。它不通过嵌套的 `npm run build` 执行生产构建，因此即使未来误加 `prebuild`，R1 验收入口也不会触发该 lifecycle hook。

门禁开始时按原始字节读取 `src/model-manifest.json`，并以 `git status --porcelain=v2 --branch --show-stash --untracked-files=all -z` 捕获包含 staged、unstaged、untracked、分支与 stash 摘要的完整 Git porcelain Buffer。结束时再次采集并逐字节比较，同时报告 manifest SHA-256。起始工作区可以是 dirty；只要求前后基线完全相同。porcelain 采集预算为 16 MiB，错误诊断采集预算为 64 KiB；超限时门禁安全失败，不尝试截断后继续验收。

任一子命令失败后立即停止后续命令，但始终执行终态完整性复核；子命令退出码优先保留。manifest 或 Git porcelain 漂移、快照失败、无法启动子命令以及可捕获的 `SIGINT` / `SIGTERM` / `SIGHUP` 都使门禁失败。门禁不会执行 restore、reset、clean、暂存、删除 `dist/` 或覆盖任何用户改动；生产构建可写入已忽略的 `dist/`。不可捕获的进程终止（例如 `SIGKILL`）、系统掉电和执行期间写后恢复为相同最终字节不属于端点快照可证明的范围。
